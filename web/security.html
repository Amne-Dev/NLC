Security Policy & Vulnerability Disclosure

Last Updated: 2026-11-06

Supported Versions

Security updates, vulnerability patches, and integrity fixes are actively maintained for the following versions:

Version Supported Status
4.0.x ✅ Supported Current active release line
< 4.0.0 ❌ Unsupported End of Life (Legacy Tkinter architecture)

Security Architecture & Safeguards

Ny-Luna Core is engineered with defensive security layers designed to safeguard player credentials and runtime integrity:

  • Credential Vault & OS-Level Encryption: Authentication tokens are never stored in cleartext. Secrets are secured using hardware-backed platform encryption (Windows DPAPI on Windows and Keyring/SecretService on Linux), reinforced by AES-256-GCM cipher encryption. Diagnostic logs automatically redact authorization headers, tokens, and credentials.
  • IPC Process Isolation: The frontend native UI (Rust / Slint) communicates with the backend daemon (Python) strictly over a local loopback boundary (127.0.0.1) with typed message framing and exception sanitization.
  • Archive Extraction & Zip-Slip Defense: Modpack and addon extractors strictly validate canonical paths, preventing directory traversal attacks (Zip Slip) outside target instance directories.
  • Cryptographic Signature Verification: Differential updates and FastCDC recipes are cryptographically verified using Ed25519 digital signatures before any binary patching occurs. Binary releases are published alongside verifiable SHA-256 checksums.

Reporting a Vulnerability

If you discover a security vulnerability or exploit within Ny-Luna Core, please disclose it privately. Please do not submit public GitHub issues or disclose sensitive details in community chat channels.

  • GitHub Security Advisories (Recommended): Submit a confidential report via our GitHub Vulnerability Reporting Portal.
  • Discord Community: Reach out directly to a verified project maintainer via direct message on our Discord Support Server.

What to Include in Your Report

To help us triage and resolve the issue quickly, please include:

  • The vulnerability category and potential impact (e.g., token leakage, path traversal, RCE).
  • The affected component and software version (e.g., v4.0.6).
  • Step-by-step reproduction instructions or a minimal proof-of-concept (PoC).
  • Any suggested remediation steps or code diffs, if available.

Response & Disclosure Timeline

Our team adheres to responsible coordinated disclosure:

  • Acknowledgment: We aim to acknowledge receipt of security reports within 48 to 72 hours.
  • Triage & Fix: We validate the report, assign severity, and develop a patch in a private security branch with adversarial regression tests.
  • Public Release: Once a patched release is published, a public advisory will be issued with full attribution to the researcher (unless anonymity is requested).
