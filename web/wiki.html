Ny-Luna Core — Architecture & Technical Wiki

Last Updated: 2026-10-29 | Launcher Version: v4.0.1

1. Overview & System Architecture

Ny-Luna Core (NLC) is a high-performance, open-source Minecraft Java Edition launcher designed for Windows and Linux. Built with a modern decoupled topology, Ny-Luna separates presentation from heavy computing to deliver native GPU-accelerated rendering and robust process isolation.

Architecture Milestone: As of v4.0.0, Ny-Luna Core transitioned from monolithic scripts to a decoupled architecture consisting of a native Rust Slint frontend, a multi-threaded Python background agent, and a standalone elevated patch supervisor.

Process Topology

The launcher coordinates across three isolated operating system processes:

Process Domain Binary / Entry Language / Framework Core Responsibilities
Frontend GUI nlc-ui / NyLuna.exe Rust & Slint UI Hardware-accelerated window chrome, interactive tabs, real-time UI state, zero-overhead input handling.
Daemon Agent agent.py / agent.exe Python 3.12+ (Daemon) Game launches, OAuth2 & Ely.by authentication, local skin proxy, Modrinth/CurseForge APIs, Discord RPC.
Patch Supervisor NLCUpdater.exe / patch_runner.py Elevated C/Python Runner Detached supervisor launched with UAC elevation to terminate locked processes and perform atomic binary updates.

IPC Protocol (GUI <—> Agent)

The GUI and the background agent communicate over standard input and standard output (stdin / stdout) using line-buffered UTF-8 JSON. Every request carries a client-generated UUID for correlation:

// Client Request (GUI -> Agent)
{"id": "7c8d9e2a-1b4f-4a88-8cf9-123456789abc", "action": "search_mods", "payload": {"query": "sodium", "loader": "fabric", "version": "1.21.1"}}

// Agent Response (Agent -> GUI)
{"id": "7c8d9e2a-1b4f-4a88-8cf9-123456789abc", "result": {"status": "success", "data": [{"id": "AANobbMI", "title": "Sodium"}]}}

Unsolicited push events (such as download progress, Discord Rich Presence updates, and game exit statuses) stream asynchronously using the event envelope:

{"event": "download_progress", "payload": {"file": "minecraft.jar", "current": 14200000, "total": 28400000, "percent": 50.0}}

2. Authentication Engines & Credential Vault

Ny-Luna supports official and third-party identity providers without compromising security or session data:

Microsoft / Mojang (Official OAuth 2.0)

  1. Device Code Flow: The launcher requests an authorization code from Microsoft Identity (https://login.microsoftonline.com/consumers/oauth2/v2.0/devicecode). The user enters the code in their browser.
  2. Xbox Live Token: The Microsoft authorization token is exchanged with user.auth.xboxlive.com to obtain an Xbox Live authentication token.
  3. XSTS Security Hash: The Xbox Live token is exchanged with xsts.auth.xboxlive.com (RelyingParty rp://api.minecraftservices.com/) to generate an XSTS token and user hash.
  4. Minecraft Access Token: The launcher contacts api.minecraftservices.com/authentication/login_with_xbox to acquire the final Bearer token, fetches game ownership entitlements, and retrieves UUID and skins.

Ely.by Account Integration

Integrates directly with Ely.by's open skin and auth architecture. The launcher authenticates against https://authserver.ely.by/auth/authenticate, retrieves an access token and profile ID, and launches Minecraft using authlib-injector directed to Ely.by servers.

Offline (Local) Profiles

Generates an offline UUID deterministically according to official Minecraft Java server specifications using MD5 version-3 namespacing:

uuid.uuid3(uuid.NAMESPACE_DNS, f"OfflinePlayer:{player_name}")

Offline profiles support custom skins and custom capes via the internal ephemeral proxy.

Credential Vault

All sensitive authentication tokens and refresh tokens are protected at rest inside launcher_config.json using an encryption vault (AES-GCM / system DPAPI keying). Plaintext secrets are never logged to disk.

3. Installations & Modloader Engine

Ny-Luna gives players total control over their game installations with clean isolation and automated modloader setup.

Supported Modloaders

Modloader Supported Minecraft Versions Setup Method Recommended Use
Vanilla All (Release & Snapshots) Mojang Version Manifest API Pure vanilla Minecraft gameplay.
Fabric 1.14 - 1.21.x+ Fabric Meta API (Automatic) Modern performance mods (Sodium, Lithium, Iris).
Forge 1.7.10 - 1.21.x Forge Maven + Installer Processor Classic modpacks and legacy overhaul mods.
NeoForge 1.20.2+ NeoForged Maven (Automatic) Modern Forge-ecosystem modpacks.
Quilt 1.18 - 1.21.x Quilt Meta API Fabric-compatible alternative ecosystem.
BatMod / LabyMod / Lunar Selected PvP Versions (1.8.9, 1.12.2, 1.16) Direct Client Hooks Competitive PvP and FPS optimization.

Instance Isolation & NTFS Junctions

Installations can be completely isolated inside their own subfolder (instances/<id>/). To avoid duplicating massive asset directories (sound libraries, textures, shader packs, and common saves), Ny-Luna uses native filesystem directory links:

  • Windows: NTFS directory junctions via _winapi.CreateJunction(). These require no Administrator privileges or Windows Developer Mode.
  • Linux / POSIX: Standard symbolic links via os.symlink().

Java Runtime Selection & JVM Tuning

Ny-Luna auto-detects system Java installations and enforces version compatibility:

  • Java 8: Required for Minecraft 1.16.5 and older (especially 1.7.10 / 1.12.2).
  • Java 17: Required for Minecraft 1.17 through 1.20.4.
  • Java 21+: Required for Minecraft 1.20.5 and newer.

The launcher includes pre-tuned Aiken G1GC arguments designed to prevent micro-stuttering during garbage collection pauses:

-XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200 -XX:+UnlockExperimentalVMOptions -XX:+DisableExplicitGC -XX:+AlwaysPreTouch -XX:G1NewSizePercent=30 -XX:G1MaxNewSizePercent=40 -XX:G1ReservePercent=20 -XX:G1HeapWastePercent=5 -XX:G1MixedGCCountTarget=4 -XX:InitiatingHeapOccupancyPercent=15 -XX:G1MixedGCLiveThresholdPercent=90 -XX:G1RSetUpdatingPauseTimePercent=5 -XX:SurvivorRatio=32 -XX:+PerfDisableSharedMem -XX:MaxTenuringThreshold=1

4. Skin System, Authlib Injection & 3D Renderer

One of Ny-Luna Core's signature features is its complete skin injection pipeline, allowing offline and Ely.by players to enjoy high-resolution custom skins and capes without patching or modifying game JARs.

JVM Injection Pipeline

Minecraft queries Mojang's session servers (sessionserver.mojang.com) at runtime via com.mojang.authlib to fetch player skin textures. Ny-Luna redirects these requests at the JVM level using yushijinhun/authlib-injector:

-javaagent:/path/to/authlib-injector.jar=http://127.0.0.1:54321

Ephemeral Local Skin Proxy (`LocalSkinServer`)

When an offline profile with a custom skin launches, Ny-Luna spawns an internal HTTP server (socketserver.ThreadingTCPServer) on a dynamic loopback port (127.0.0.1:0). The server implements the Yggdrasil API protocol:

  • GET /: Handshake verification. Responds 200 OK with the mandatory HTTP header: 
    X-Authlib-Injector-API-Location: /
  • POST /api/profiles/minecraft: Returns the player's offline UUID and username.
  • GET /sessionserver/session/minecraft/profile/<uuid>: Serves a base64-encoded Yggdrasil profile payload specifying the local texture URL and skin model (classic / 4px arm or slim / 3px arm).
  • GET /textures/skin.png: Streams the user's local skin PNG directly from disk into the running game client.

Software 3D Skin Preview Engine

Ny-Luna includes a software rasterizer built on Pillow and NumPy that renders interactive 3D character previews in the Locker without requiring an OpenGL context or GPU driver allocation:

  • Converts legacy 64x32 skin sheets to modern 64x64 format with second-layer alpha overlays.
  • Applies real-time pitch and yaw rotation matrices: R_cam = R_pitch × R_yaw.
  • Animates walking limb swings (θ_leg = 26° × sin(ω)) and cape flutter (6° + 6° × |sin(ω)|).
  • Computes surface normal vectors (N_cam) and eliminates back-facing polygons before rendering with directional sun lighting.

5. Modpacks, Mods & Modrinth Integration

Ny-Luna offers integrated mod management with support for both the open-source Modrinth ecosystem and CurseForge modpack archives.

Modrinth Browser & `.mrpack` Engine

Search, filter, and install mods, resource packs, and shader packs directly from Modrinth:

  • Index Parsing: Extracts modrinth.index.json, validating Minecraft and modloader compatibility.
  • Cryptographic Verification: Downloads mod binaries in parallel, validating every file against SHA-1 and SHA-512 hashes from the index.
  • Override Extraction: Unpacks overrides/ and client-overrides/ safely into the instance root with directory-traversal (Zip Slip) guards.

CurseForge Modpack Importer

Import standard CurseForge .zip exports. Ny-Luna reads manifest.json, resolves project IDs and file IDs via the CurseForge API, and automates downloads. A custom API key can be supplied in Settings for restricted third-party packs.

Non-Destructive Mod Toggling

Disable individual mods without deleting files or losing configurations. Ny-Luna renames inactive mods with a .disabled suffix (e.g., sodium-0.5.jar.disabled), causing Minecraft modloaders to bypass them during initialization.

6. Addons & Extensibility Ecosystem

Ny-Luna includes an extensible addon system allowing community developers to add new features via decoupled Python workers without modifying the core launcher binary.

Addon Manifest & Structure

Addons reside in %APPDATA%/.nlc/addons/<addon_id>/ (Windows) or ~/.nlc/addons/<addon_id>/ (Linux):

my_addon/
├── addon.json       # Manifest declaring metadata and actions
└── main.py          # Entry point handling action dispatches

Example addon.json:

{
    "id": "quick_backup",
    "name": "World Quick Backup",
    "version": "1.0.0",
    "author": "Community",
    "description": "Creates timestamped ZIP backups of your Minecraft saves folder.",
    "actions": [
        {
            "id": "create_backup",
            "name": "Backup Active World",
            "inputs": [{"name": "world_name", "type": "string"}]
        }
    ]
}

Built-in Addon Features

  • Streamer Mode: Conceals private data on screen, including Minecraft usernames, UUIDs, auth tokens, and local file paths.
  • Server Monitor: Live TCP pings, MOTD parsing, online player counters, and real-time server latency meters.
  • Playtime Tracker: Tracks active game runtime per installation and account across offline and online sessions.
  • Screenshot Gallery: In-launcher viewer to inspect, open, copy, and delete full-resolution in-game screenshots.

7. Differential FastCDC Updates & Security

Ny-Luna implements differential updates powered by FastCDC (Content-Defined Chunking) and Ed25519 cryptographic signatures, shrinking multi-megabyte app updates to tiny delta patches.

Gear Rolling Hash Algorithm

Unlike fixed-size chunking (which breaks completely upon a single byte insertion), FastCDC slides a 32-bit Gear lookup table over the binary stream to determine natural chunk boundaries:

  • Min Chunk: 16 KB (prevents micro-fragmentation).
  • Avg Chunk: 64 KB (optimal bandwidth-to-overhead ratio).
  • Max Chunk: 256 KB (caps maximum chunk size).
  • Boundary Mask: fp & 0x0000FFFF == 0 triggers a chunk cut.

Range Coalescing & Cryptographic Signatures

  1. Ed25519 Verification: The launcher fetches the update manifest (newlauncher.exe.cdc.json) and verifies its Ed25519 signature before reading any data.
  2. Local Chunk Deduplication: Existing local binary chunks are indexed by SHA-256 and copied directly into a temporary .part file with zero network usage.
  3. HTTP Range Coalescing: Missing chunk gaps smaller than 32 KB are merged into single HTTP Range requests, eliminating redundant TLS handshakes.
  4. Atomic Binary Promotion: The full target binary is verified against the signed whole-file SHA-256 before swapping into place.

8. File System Layout & Configuration

All persistent files, settings, and cache directories follow strict cross-platform conventions:

Directory Locations

Operating System Launcher Data Root Game Directory (Default) Installation Dir
Windows %APPDATA%\.nlc %APPDATA%\.minecraft %LOCALAPPDATA%\Programs\Ny-Luna
Linux ~/.nlc ~/.minecraft /opt/new-launcher

Atomic Persistence Protocol

To eliminate configuration corruption caused by sudden system shutdowns or power loss, ConfigManager executes atomic writes:

1. Create temp file `nlc_cfg_*.tmp` strictly inside the config parent directory.
2. Write UTF-8 JSON payload, flush user-space buffers, and call `os.fsync()`.
3. Create a backup copy of the existing configuration as `launcher_config.json.bak`.
4. Atomically promote temp file to `launcher_config.json` via `os.replace()`.

9. Command-Line Interface (CLI Reference)

Ny-Luna can be executed from terminal scripts, desktop shortcuts, and automation tools using the nlc binary command (or legacy newlauncher alias).

# Launch standard GUI
nlc

# Launch in headless daemon mode
nlc --agent

# Launch directly into a specific installation
nlc --instance "Survival 1.21" --account "Steve"

# Launch with verbose debug logging
nlc --debug

CLI Arguments Matrix

Flag Parameters Description
--help, -h None Print complete command-line syntax and exit.
--version, -v None Display the installed launcher version.
--agent, --backend None Run the headless background Python agent directly.
--instance <id> Directly launch a specified Minecraft installation.
--account <username> Select the active account for direct launch.
--offline-user <name> Launch immediately with an offline username profile.
--dir <path> Override the root Minecraft directory.
--debug None Enable verbose debug output to terminal and log files.

10. Diagnostics & Troubleshooting Guide

Common troubleshooting scenarios and solutions:

Linux: AppImage FUSE Library Missing

AppImages require the user-space FUSE runtime. If launching the AppImage yields an error like dlopen(): error loading libfuse.so.2:

  • Ubuntu 22.04 LTS & Debian 12: sudo apt install -y libfuse2
  • Ubuntu 24.04 LTS & Newer: sudo apt install -y libfuse2t64
  • Arch Linux / Manjaro: sudo pacman -S fuse2
  • Fedora: sudo dnf install fuse

Minecraft Crash Exit Codes

Exit Code Common Cause Resolution Steps
Exit 0 Clean shutdown or manual quit. Normal behavior.
Exit 1 Mod conflict, missing dependency, or invalid Java argument. Check latest.log. Check that mod versions match your loader. Remove recently added mods one by one.
Exit -1073740791
(0xC0000409)		 GPU driver crash or incompatible overlay (RivaTuner, GeForce Experience, Discord overlay). Update graphics drivers (NVIDIA / AMD / Intel) and disable third-party in-game overlays.
Exit 137 Linux Out-of-Memory (OOM) killer terminated the JVM. Increase RAM allocation in Settings or close heavy background applications.

Where to Find Log Files

  • Launcher Crash Logs: %APPDATA%\.nlc\logs\crash.log (Windows) or ~/.nlc/logs/crash.log (Linux).
  • Background Agent Logs: %APPDATA%\.nlc\logs\agent.log (Windows) or ~/.nlc/logs/agent.log (Linux).
  • Minecraft Game Logs: .minecraft/logs/latest.log or instances/<id>/.minecraft/logs/latest.log.
